# 唐何的 AI 产品技能库

把产品实践中的判断方法整理成 5 个可复用的 Skill，覆盖体验检查、需求评审、Agent 方案取舍、失败诊断和开发交接。

这些内容在本仓库独立编写，以 Commexa 工业询价、OrgMesh 企业知识和食光饮食记录等场景组织方法。仓库中的示例输入均为构造材料，用于解释判断过程，不是线上业务记录或效果统计。

| Skill | 什么时候用 | 得到什么 |
| --- | --- | --- |
| [AI 产品体验审查](skills/ai-ux-review/SKILL.md) | AI 功能看起来能用，需要检查用户能否理解、纠错和继续操作 | 有证据的问题、修改建议与验证方式 |
| [AI PRD 审查](skills/ai-prd-reviewer/SKILL.md) | 需求准备交给研发，模型边界和验收条件尚不清楚 | 契约缺口、例外分流和可验收的需求修订 |
| [Agent 适用性判断](skills/agent-fit-analyzer/SKILL.md) | 需要判断某段业务该用规则、助手、工作流还是 Agent | 各环节的实现形态、执行权限与交接条件 |
| [BadCase 诊断](skills/badcase-diagnosis/SKILL.md) | 已有失败样本，需要定位问题并安排修复 | 证据链、首个偏离点、修复位置和回归样本 |
| [AI Coding 任务交接](skills/ai-coding-handoff/SKILL.md) | 产品方案需要变成可以执行的开发任务 | 页面、接口、数据、异常处理和验收条件组成的任务包 |

## 使用

每个 `skills/<名称>/` 都是一份独立技能，入口为 `SKILL.md`。`agents/openai.yaml` 提供界面名称和示例调用；`references/example.md` 提供对应场景的构造示例。

在支持本地 Skill 的工具中加入所需的技能目录后，可以这样发起任务：

```text
用 $ai-ux-review 检查照片识别、结果复核和确认保存这条流程。

用 $ai-prd-reviewer 审查这份工业询价选品工作台需求，重点检查缺数量、禁止替代和报价改版。

用 $agent-fit-analyzer 判断企业知识查询中哪些环节需要 Agent，哪些适合固定流程。

用 $badcase-diagnosis 分析这些被员工更换的推荐，先区分选错商品和业务条件变化。

用 $ai-coding-handoff 把“采用候选商品”方案整理成开发任务，包含状态保存和重复提交处理。
```

没有启用 Skill 的环境，也可直接阅读对应文件，将工作流用于人工评审。不同工具的技能目录和加载方式，以其文档为准。

## 使用边界

这套技能帮助完成分析和交接，不自带检索、ERP、语音、相机或数据库服务。它们不会因为被加载，就获得发送报价、下单、公开资料或修改生产数据的授权。

缺少样本、日志或实测时，输出应保留未知项和验证方法；示例不能写成个人已经实现的功能或已经取得的业务成绩。
