# 企业知识与询价任务的取舍示例

以下是方案比较的构造场景，不是系统完成状态声明。

## OrgMesh：员工查询一项制度

目标是回答问题，并让员工定位有权查看的原始资料。

- 识别问题中的术语、检索资料和整理回答需要语义能力。
- 如果默认流程就是检索、筛选、组织答案与展示引用，可以采用有边界的检索工作流。
- 当问题确实要求在多个异构工具间调查、根据新证据决定下一步，才评估受限的动态 Agent。
- 无论使用哪种形态，来源访问权限都应由真实身份与权限机制检查；不能通过提示词声明代替。
- 索引暂时没有资料与员工没有访问权限应分别处理，避免使用不该显示的片段解释“无权限”。

## Commexa：从询价到报价草稿

| 环节 | 合适的初始选择 | 理由 |
| --- | --- | --- |
| 采购清单结构化 | 模型抽取与规则校验 | 语言不固定，但输出字段可以校验 |
| 完整型号查目录 | 确定性查询优先 | 无需让模型自由规划搜索过程 |
| 描述性需求查找候选 | 受控的混合检索工作流 | 可观察召回、重排和证据 |
| 编码冲突或缺资料 | 内部核对队列 | 对应岗位能够补充内部事实 |
| 权威价格查询 | 业务接口 | 价格不由模型生成 |
| 报价审批和发送 | 有版本约束的业务流程 | 商业动作需要明确授权和可追踪状态 |

可以先比较固定流程与受限 Agent 在复杂描述、跨目录调查等样本上的表现。检验点是复杂任务是否更容易完成，以及增加了多少等待、调用成本和人工核对，不能只比较生成答案是否流畅。
