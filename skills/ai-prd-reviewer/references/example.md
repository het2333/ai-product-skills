# Commexa：逐行选品需求的构造示例

## 待评审需求

“读取客户采购清单，匹配商品并自动生成报价。有不明确的内容就询问客户。”

构造样本：

| 原始行 | 已知条件 | 需要区分的处理 |
| --- | --- | --- |
| MCB-C16，12 只 | 完整型号，目录存在唯一结果 | 推荐商品，仍由员工确认数量与采用 |
| 接触器，AC220V，数量未写 | 需求缺数量，规格也可能不足 | 先保留空值，澄清会影响选型或报价的信息 |
| 同一厂家型号映射两个内部编码 | 客户需求完整 | 内部编码核对，不要求客户选择内部编码 |
| 指定型号，不接受替代 | 原型号无库存 | 保留禁止替代约束，不能把相似商品视作可采用答案 |

## 建议补入的行为

1. 保留每条需求的原文锚点、数量、单位与替代许可。数量缺失不能默认写成 1；不明确的替代许可不能推定为允许。
2. 将“客户需求不完整”“内部编码冲突”“目录资料不足”“无匹配”分别作为处理原因。
3. 推荐商品与查询价格分开。价格取自指定业务来源；模型不能自行补造客户价或交期。
4. 员工采用后保存商品、数量、采用人和需求版本。原文或商品发生重要变化时，重新核对受影响的报价行。
5. 报价内容改版后，旧版审批不能直接授权新版本发送。

## 可验收的例子

输入同型号双内部编码的需求行，系统进入内部核对队列；客户澄清队列没有新增该问题，原文与两个候选仍可查看。

编辑已审批报价的数量后，展示新版本待审批状态；在接口层尝试使用旧版本审批发送，应被拒绝，且没有产生已发送业务记录。
