# 食光：照片记录流程的体验审查示例

以下是构造输入，用于演示审查方法。

## 给定材料

- 用户从相册选了一张午餐照片。
- 模型返回“米饭、鸡肉、蔬菜”及估算份量。
- 结果页允许修改份量，但“完成”按钮没有说明是否保存。
- 网络失败后弹出“请重试”，页面返回空白拍照入口。
- 评审者只有页面截图，没有运行后端。

## 应当识别的问题

| 观察 | 对任务的影响 | 建议及验证 |
| --- | --- | --- |
| “完成”可能表示分析结束，也可能表示保存 | 用户不知道是否还需确认 | 按实际行为命名为“确认并保存”；用已保存记录及返回总览的内容验证 |
| 估算值没有说明 | 用户可能把模型估计当成精确测量 | 展示估算属性，保留份量和营养字段的修改入口 |
| 重试后原图与修改消失 | 用户要重新开始，人工纠错成本被浪费 | 保留选图和已修改字段，明确哪些步骤重跑 |
| 只有截图 | 无法确认请求是否幂等或记录是否落库 | 将重复保存和持久化行为列为待验证，不直接宣布存在重复写入缺陷 |

评审过程中无需为了证明语音入口存在而启动麦克风，也无需保存一条健康记录来评价按钮文案。需要测试这些行为时，按当前任务的实际授权和测试环境执行。
